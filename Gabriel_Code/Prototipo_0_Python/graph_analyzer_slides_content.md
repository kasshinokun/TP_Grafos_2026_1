## Slide 2: O que é Event-Driven Architecture (EDA)?

### Desacoplamento e Reatividade

A **Arquitetura Orientada a Eventos (EDA)** é um paradigma de design de software que promove o desacoplamento entre os componentes do sistema. Em vez de chamadas diretas, os componentes se comunicam através da emissão e consumo de eventos.

**Características Principais:**
- **Assíncrona:** Operações não bloqueiam o fluxo principal.
- **Desacoplada:** Componentes não precisam conhecer a implementação uns dos outros.
- **Escalável:** Facilita a adição ou modificação de funcionalidades.
- **Reativa:** Responde a mudanças de estado ou ações do usuário.

## Slide 4: Comunicação entre Micro-aplicações

### Simulação de Requisições GET e POST

As micro-aplicações do GraphAnalyzer se comunicam de forma assíncrona, simulando requisições HTTP (GET e POST) através do `EventBus`.

- **Requisições (POST):** Uma micro-aplicação publica um evento com um tipo específico (ex: `API_POST_CREATE_GRAPH`) e um `payload` (dados).
- **Respostas (GET):** Outra micro-aplicação, ao receber um evento de requisição, processa-o e publica um evento de resposta (ex: `RESPONSE_GET_STUDENTS`) com os dados solicitados.

Este modelo garante que as micro-aplicações não tenham conhecimento direto umas das outras, facilitando a manutenção e a evolução do sistema.

## Slide 5: Implementação com PyQt6

### Interface Reativa e Gerenciamento de Eventos

O **PyQt6** é utilizado para construir a interface gráfica do usuário (`UIMicroApp`), aproveitando seu sistema de sinais e slots para uma integração eficiente com a EDA.

- **`QObject` e `pyqtSignal`:** O `EventBus` é implementado como um `QObject` e utiliza `pyqtSignal` para a emissão de eventos, garantindo que a comunicação seja thread-safe e se integre perfeitamente ao loop de eventos do Qt.
- **Interface Reativa:** A UI reage aos eventos publicados pelas outras micro-aplicações, atualizando seus componentes de forma dinâmica sem bloquear a interface.

## Slide 6: Estrutura do Projeto

### Organização Modular

A estrutura de diretórios reflete a modularidade da arquitetura, separando as responsabilidades de cada componente:

```
/graph_analyzer/
├── main.py                 # Ponto de entrada da aplicação
├── core/
│   ├── event_bus.py        # Implementação do EventBus (Singleton)
│   └── base_app.py         # Classe base para micro-aplicações
├── apps/
│   ├── data_app.py         # Micro-aplicação de dados (Backend)
│   ├── graph_app.py        # Micro-aplicação de lógica de grafos
│   └── ui_app.py           # Micro-aplicação de interface do usuário
└── models/
    ├── graph_models.py     # Definições das classes de grafos
    └── student_models.py   # Modelo de dados dos alunos
```

## Slide 7: Fluxo de Interação (Exemplo)

### Carregando Alunos e Criando Grafo

1.  **UI:** Usuário clica em "Carregar Alunos".
2.  **UI (internamente):** `UIMicroApp` publica `API_GET_STUDENTS` no `EventBus`.
3.  **EventBus:** Encaminha `API_GET_STUDENTS` para `DataMicroApp`.
4.  **DataMicroApp:** Processa a requisição, obtém a lista de alunos e publica `RESPONSE_GET_STUDENTS` no `EventBus`.
5.  **EventBus:** Encaminha `RESPONSE_GET_STUDENTS` para `UIMicroApp`.
6.  **UI:** `UIMicroApp` atualiza a tabela de alunos na interface.
7.  **UI:** Usuário clica em "Inicializar Grafo".
8.  **UI (internamente):** `UIMicroApp` publica `API_POST_CREATE_GRAPH` (com número de nós) no `EventBus`.
9.  **EventBus:** Encaminha `API_POST_CREATE_GRAPH` para `GraphMicroApp`.
10. **GraphMicroApp:** Cria a estrutura do grafo e publica `RESPONSE_POST_CREATE_GRAPH` no `EventBus`.
11. **EventBus:** Encaminha `RESPONSE_POST_CREATE_GRAPH` para `UIMicroApp`.
12. **UI:** `UIMicroApp` exibe uma mensagem de sucesso.

## Slide 8: Benefícios da Arquitetura EDA no GraphAnalyzer

### Vantagens do Design Modular

- **Manutenibilidade:** Facilita a identificação e correção de problemas, pois cada micro-aplicação é uma unidade isolada.
- **Extensibilidade:** Novas funcionalidades ou micro-aplicações podem ser adicionadas sem impactar o restante do sistema.
- **Testabilidade:** Componentes podem ser testados de forma independente, simplificando o processo de QA.
- **Flexibilidade:** Permite a evolução tecnológica de componentes individuais sem a necessidade de reescrever todo o sistema.
- **Escalabilidade:** Embora neste projeto as micro-aplicações rodem no mesmo processo, a arquitetura EDA é fundamental para sistemas distribuídos, permitindo que micro-serviços rodem em ambientes separados.

## Slide 9: Conclusão

### Um Modelo Robusto para Aplicações Complexas

A arquitetura Event-Driven, combinada com o poder do PyQt6, oferece um modelo robusto e flexível para o desenvolvimento de aplicações complexas como o GraphAnalyzer. O desacoplamento e a comunicação assíncrona são pilares para sistemas modernos e de fácil manutenção.
